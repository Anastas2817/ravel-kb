# C1 — System: контекст и границы системы

Дополнение к диаграмме [C1 System](assets/c4/C1.png). Здесь зафиксированы назначение, акторы, сценарии и границы системы — то, что на одноэкранной диаграмме не помещается.

## 1. Назначение системы

Ravel — десктопное приложение для ручного проектирования персональных баз знаний в форме ориентированного графа с типизированными связями. Структура строится пользователем осознанно — каждый узел и каждая связь добавляются вручную, а система только советует: обнаруживает циклы, выделяет хабы, раскладывает граф семантически (общее сверху, онтологические ленты по горизонтали). Цель — дисциплина мышления через структуру, а не автоматическое «собирание знаний».

## 2. Акторы

| Актор | Тип | Роль |
|---|---|---|
| Пользователь (автор базы знаний) | человек | студент, исследователь, интеллектуальный работник, ведущий конспект/карту понятий |
| Файловая система / JSON-файлы | внешняя система | хранение и перенос баз знаний между машинами |

Внешних сервисов, ролей с разными правами и вторых акторов нет: система single-user, офлайн.

## 3. Потребности акторов

- **Пользователь:** осознанно структурировать знания (не свободные рисунки, а типизированный граф с семантикой связей); видеть иерархию и онтологические классы как пространственную карту, а не список; сохранять и переносить базу; получать подсказки о проблемах структуры (циклы, перегруженные хабы) **без потери ручного контроля** — автоматика советует, пользователь решает.
- **Файловая система (как среда):** единственный носитель состояния — обычный JSON-файл, читаемый человеком и версионируемый через git.

## 4. Ключевые сценарии (use cases)

1. Создать / удалить узел / связь заданного типа (вручную, через канвас).
2. Загрузить карту из JSON-файла; сохранить карту в JSON-файл.
3. Разложить граф автоматически (иерархическая раскладка с онтологическими лентами).
4. Вручную переопределить позицию узла (ручная позиция имеет приоритет над раскладкой).
5. Отменить / повторить действие (undo/redo).
6. Получить подсказку: обнаружен цикл; узел-«хаб» перегружен связями.

## 5. Функциональные границы (in-scope)

- CRUD узлов, связей и типов узлов/связей (типы задаются в JSON).
- Сериализация/десериализация карты в JSON с версией формата (`format_version`).
- Иерархическая раскладка (модифицированный Сугияма) с ограничением на онтологические ленты.
- Анализ структуры: обнаружение циклов, подсветка хабов.
- Канвас: перемещение узлов, создание связей drag'ом, цветовое кодирование по типам.
- Undo/redo через паттерн Command.

## 6. Явные исключения (out-of-scope)

Продуктовые ограничения (> 10³ узлов, нет синхронизации/облака/коллаборации, нет импорта, несовместимость формата, типы через JSON в MVP) — в [spec.md](spec.md) §7; дублировать их здесь не будем. Исключения именно уровня «границы системы»:

- LLM-генерация структуры и текста (link prediction — без LLM, исследовательская рамка в [research.md](research.md));
- мобильные платформы; веб-версия; клиент-серверная архитектура;
- плагины и скрипты пользователя.

## 7. Внешние зависимости

Полная таблица зависимостей — в [README](../README.md) «Зависимости». С точки зрения C1 важно другое: сторонних сервисов нет — ни платёжных шлюзов, ни OAuth, ни сетевых API. Работа в runtime полностью офлайн; интернет нужен один раз — при первой конфигурации CMake (FetchContent).

## 8. Ограничения верхнего уровня

- **Платформы:** десктоп Windows / Linux / macOS (сборка MSVC 2022 и gcc/clang; CI — windows-2022 и ubuntu-latest, Debug/Release).
- **Нагрузка:** один пользователь, один файл; лимит ~10³ узлов — см. [spec.md](spec.md) §7. Пересечения рёбер считаются один раз после раскладки (O(E²) попарных проверок) и кэшируются.
- **SLA:** не применимо (локальное приложение без сервисных обязательств); корректность важнее скорости — любой файл, нарушающий инварианты, отклоняется при загрузке с понятной ошибкой.
- **География/регуляторика:** не применимо; данные не покидают машину пользователя.
