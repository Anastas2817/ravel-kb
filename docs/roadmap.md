# Дорожная карта (MVP курсовой работы)

**Горизонт: 12 недель, нагрузка 1–2,5 часа в день.** План намеренно аскетичен: это объём, который выполним без выгорания, — а проект автор продолжит вне курсовой, поэтому всё «мечтательное» уехало в [perspectives.md](perspectives.md) и в хвост.

Каждая неделя заканчивается работающим состоянием, которое можно показать. Буферы заложены явно.

## Этап 1. Ядро (недели 1–3)

**Результат:** модель и сериализация покрыты тестами, CI зелёный.

- [x] Неделя 1: модель данных `Graph` (узлы, рёбра, типы), инварианты, генерация `id` (раздельные счётчики `next_id_node` / `next_id_relation`, ADR-001); юнит-тесты на инварианты (GoogleTest, без Qt)
- [ ] **🚧 в работе** Неделя 2: `JsonStorage`: `format_version`, счётчики `next_id_*`; round-trip тесты (save → load → save)
- [ ] Неделя 3: тесты на некорректные файлы (битый JSON, дубли `id`, нет `format_version`, `next_id_*` ≤ максимального id своего вида); CI: сборка + тесты на push (GitHub Actions, job `core` без Qt)

## Этап 2. Канвас (недели 4–5)

**Результат:** приложение запускается, узлы и связи создаются вручную, файл сохраняется и загружается.

- [ ] Неделя 4: `QGraphicsScene/View`: узлы перемещаемы, рёбра следуют за узлами
- [ ] Неделя 5: создание узла (двойной клик / `N`), создание связи drag'ом с диалогом выбора типа, удаление, сохранение/загрузка

## Этап 3. Раскладка (недели 6–8)

**Результат:** граф раскладывается автоматически; цвет кодирует тип; циклы подсвечены.

- [ ] Неделя 6: обнаружение циклов (DFS) интегрировано в раскладку: обратные рёбра не задают слои, подсветка + предупреждение (spec.md §5.4)
- [ ] Неделя 7: **этап 3a** — топологическая слоистость (longest-path или network simplex) → минимизация пересечений методом барицентров **внутри онтологических лент** (перестановки между лентами запрещены, spec.md §5.2); тесты: слоистость, пересечений меньше, чем у наивной раскладки, на графах ≤ 20 узлов
- [ ] Неделя 8: **этап 3b** — назначение координат (Brandes–Köpf или priority method) с ограничением на ленты: блоки выравнивания не должны пересекать границы лент. Это самая трудоёмкая фаза — буфер обязателен
- [ ] Неделя 8: **этап 3c** — визуальное смягчение межленточных пересечений (fading по числу пересечений: opacity 0.3–0.5 для рёбер выше порога; hover-подсветка связанного, остальное тускнеет — пересечения не устраняются, но карта читаема без изменения алгоритма; подсчёт числа пересечений — O(E²) попарных проверок сегментов, поэтому считается один раз после раскладки и кэшируется, пересчёт только при изменении геометрии); кнопка «Разложить» с сохранением ручных переопределений; цветовое кодирование узлов и связей по типам

## Этап 4. Команды и финал (недели 9–12)

**Результат:** undo/redo работает; комплект документации; демонстрационная база знаний.

- [ ] Неделя 9: `Command` + `AddNodeCmd`, `AddEdgeCmd`, `MoveNodeCmd`, `RemoveNodeCmd`; undo/redo; тесты «do → undo → состояние совпадает»
- [ ] Неделя 10: пример базы знаний (20–30 узлов, матанализ); скриншоты «до/после раскладки» в README
- [ ] Неделя 11: покрытие тестами ядра ≥ 50 % строк (lcov); Doxygen по публичному API; актуализация README/spec
- [ ] Неделя 12: буфер (багфиксы, ответы на типовые вопросы к защите); репетиция демонстрации

## Метрики успеха (MVP)

| Метрика | Цель | Как измеряется |
|---|---|---|
| Round-trip save → load → save | семантическое совпадение: те же узлы, рёбра, типы, счётчики `next_id_*`; порядок ключей и элементов не важен | автотест сравнивает нормализованные структуры (парсинг обоих JSON и глубокое сравнение, а не байтовое) |
| Пересечения рёбер на тестовом графе (20 узлов) | меньше, чем у наивной слоистой раскладки | счётчик пересечений |
| Покрытие тестами ядра | ≥ 50 % строк | lcov / ctest |
| CI | зелёный пайплайн на каждом коммите | GitHub Actions |

*(Бенчмарки на 10²–10³ узлов убраны из MVP — лимит проекта 10³ узлов, а измерения производительности вынесены в перспективы.)*

## Риски и запасные планы

**Главный технический риск проекта — модифицированный Sugiyama с онтологическими лентами (этапы 3a/3b).** Это осознанно самая трудная часть: ограничение на ленты нестандартно, а назначение координат с этим ограничением (блоки выравнивания не пересекают границы лент) — самая сложная фаза классического алгоритма. Риск принят, и для него есть план деградации: **провал раскладки ≠ провал проекта** — каждая ступень ниже это работающий, показываемый результат.

**Критерий перехода на запасной план (конец недели 8).** Переходим на F2, если выполнено хотя бы одно: (а) 3b не работает на тестовых графах ≤ 20 узлов; (б) пересечений на тестовом графе не меньше, чем у наивной раскладки; (в) 3b съедает буфер недели 8 и угрожает этапу 4. Решение фиксируется в репозитории (коммит + заметка в README) — откат на F1 после перехода не планируется.

**Лестница деградации:**

- **F1 (основной план).** Полный Sugiyama: слоистость → барицентры внутри лент → координаты с блоками выравнивания внутри лент (этапы 3a, 3b).
- **F2 (запасной).** Классический Sugiyama без жёсткого ограничения на ленты: барицентры свободны, принадлежность к ленте учитывается как мягкий приоритет (стабильная сортировка по (лента, барицентр)). Метрика «пересечений меньше, чем у наивной раскладки» при этом сохраняется.
- **F3 (гарантированный минимум).** Наивная слоистая раскладка: слои по longest-path, порядок внутри слоя — по классу и id. Без оптимизации пересечений, но с честной семантической вертикалью (общее сверху) и детерминированностью.
- **Во всех вариантах.** Ручное переопределение позиций (spec.md §5.5): карта остаётся полезной даже без автоматической раскладки.

**Что не зависит от успеха раскладки.** Цикл-детекция, цветовое кодирование, undo/redo, JSON, канвас делаются в любом сценарии — провал 3b отрезает только «красивую» часть, не ядро.

**Второй риск — неделя 9 превратится в рефакторинг.** Если недели 4–5 писать канвас с прямым доступом к `Graph`, неделя 9 (команды) потребует переписать весь UI. Митигация: все действия канваса с первого дня оформляются командами (пока без стеков undo/redo) — тогда неделя 9 добавляет только стеки.

**Порядок жертв при нехватке времени (по убыванию безболезненности).** Этап 3c (fading — косметика) → часть полировки цветов → объём Doxygen (оставить док-комментарии только к публичному API ядра). Никогда не режем: тесты инвариантов, round-trip, undo/redo.

## После курсовой: веха «свой конспект»

Критерий того, что проект жив и нужен: к концу учебного года — собственный конспект на 100+ узлов, который ведётся в Ravel, а не в Coggle/Excalidraw. Эта веха важнее любых внешних метрик (звёзды, пользователи): совпадение автора и пользователя — главный двигатель проекта. До достижения вехи новые фичи из perspectives.md не начинаются.
